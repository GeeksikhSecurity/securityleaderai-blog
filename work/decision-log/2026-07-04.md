# Decision Log — 2026-07-04

## Set up the Daily Decision Digest workflow

- **Working on:** Adding a daily work log with decision capture to the project.
- **Options considered:** (a) Real-time logging of every action as it happens; (b) end-of-day rollup with lightweight decision notes during work.
- **Chose:** End-of-day rollup with lightweight capture. Notes go to `work/decision-log/YYYY-MM-DD.md` during work; a summarizer turns them into `outputs/daily-summary-YYYY-MM-DD.md` at day's end.
- **Skipped:** Real-time logging.
- **Why (plain English):** Real-time logging sounds ideal but becomes noisy and fragile — it interrupts the work and produces a log nobody reads. Small notes during work plus one readable digest per day keeps the burden low and the artifact useful.
- **Also decided:** The summarizer is a separate pass (skill/sub-agent) that only summarizes — the main coding agent keeps making the decisions. The digest must be traceable to the notes and git history, never invented after the fact.
- **Changed:** `CLAUDE.md` (new "Daily Decision Digest" section), `.claude/skills/daily-decision-digest/SKILL.md` (summarizer skill), `work/decision-log/README.md` (note format), `outputs/README.md`, this file, `outputs/daily-summary-2026-07-04.md`. Plus a daily scheduled trigger (23:30 UTC) to run the digest automatically.
- **Verified:** `npm run lint` (tsc --noEmit) and content lint run after the change — results recorded in the digest.
- **Follow-up:** Consider a lint rule that flags a `work/decision-log/<date>.md` with commits that day but no matching `outputs/daily-summary-<date>.md`. Adjust the trigger time if 23:30 UTC doesn't match the actual end of the working day.
